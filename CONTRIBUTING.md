# Contributing

Contributions are welcome! Whether it's adding documentation, fixing errors, or sharing new techniques.

## Guidelines

### Content
- Write clearly and concisely
- Include examples and commands where applicable
- Link to external resources and citations
- Test procedures before documenting
- Use Markdown formatting consistently

### Structure
- Follow the folder organization of the repo
- Use descriptive file names
- Include a brief header describing the content
- Link related topics

### Security & Privacy
- Do not include production credentials, API keys, or sensitive data
- Sanitize real hostnames, IPs, and domain names with examples (e.g., `example.com`, `192.0.2.0/24`)
- If describing a real infrastructure, generalize or anonymize details

### Commit Messages
- Use clear, descriptive commit messages
- Reference the topic or section you're adding/updating
- Example: "Add PostgreSQL backup procedures" or "Fix Nginx SSL configuration examples"

## Process

1. Fork or create a branch
2. Add or update content
3. Test the content if applicable
4. Commit with a clear message
5. Submit a pull request or push to main

---

Questions? Open an issue or reach out to the maintainers.
